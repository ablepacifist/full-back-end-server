# Rich Media Chat — Images, GIFs & Hyperlinks

## Overview

This document details exactly what needs to be implemented to add **image uploads**, **GIF embeds**, and **clickable hyperlink** support to the mumble-bridge text channels. It covers backend changes (both Lexicon and bridge-side), frontend rendering, and the recommended storage strategy.

---

## Storage Decision: Lexicon Backend (recommended)

**Use the Lexicon backend for everything.** Here's why:

| Concern | Lexicon Backend | MySQL (bridge DB) |
|---|---|---|
| **Message history** | Already stores all messages via `POST /api/messages` with `messageType` and `mediaFileId` fields | Would duplicate storage; messages already go to Lexicon |
| **File storage** | Lexicon already has a media library (`/api/media/*`) — files uploaded there are accessible via streaming URLs | Would require building a new file storage system from scratch on the bridge |
| **User attribution** | Lexicon ties uploads to authenticated players | Bridge would need its own file ownership tracking |
| **Persistence** | Lexicon's HSQLDB persists across restarts | Same for MySQL, but adds another system to maintain |
| **Access from Lexicon frontend** | Media is natively available in Lexicon's React UI | Lexicon frontend would need to call the bridge's API instead |

**Summary:** The Lexicon backend already has message storage with `messageType` and `mediaFileId` fields, plus a full media library. We just need the Lexicon team to add a few small API endpoints and we wire them into the bridge.

## What the Lexicon Team Needs to Add

### 1. Chat Media Upload Endpoint

We need an endpoint that accepts image/GIF uploads specifically for chat messages (separate from the existing media library which is for music/video).

```
POST /api/chat/upload
Content-Type: multipart/form-data

Fields:
  - file: The image/GIF file (required)
  - userId: Lexicon user ID of uploader (required)
  - channelId: Mumble channel ID where the file was shared (required)

Response (200 OK):
{
  "id": 12345,
  "url": "/api/chat/files/12345",
  "thumbnailUrl": "/api/chat/files/12345/thumb",
  "originalFilename": "screenshot.png",
  "mimeType": "image/png",
  "width": 1920,
  "height": 1080,
  "fileSize": 245760,
  "uploadedBy": 7,
  "createdAt": "2026-04-03T12:00:00Z"
}
```

**Requirements:**
- Accept MIME types: `image/jpeg`, `image/png`, `image/gif`, `image/webp`
- Max file size: **8 MB** (larger than avatars since these are content)
- Generate a thumbnail (max 400px wide) for inline display
- Store files on disk under a `chat-uploads/` directory (or wherever Lexicon stores media)
- Return dimensions (`width`, `height`) so the frontend can size `<img>` tags before load
- GIFs: serve the original file (don't convert to static image)

### 2. Chat File Serving Endpoint

```
GET /api/chat/files/{fileId}
→ Serves the original uploaded file with correct Content-Type header

GET /api/chat/files/{fileId}/thumb
→ Serves the thumbnail (max 400px wide, JPEG/WebP)
```

**Requirements:**
- Set `Content-Type` header correctly (`image/png`, `image/gif`, etc.)
- Set `Cache-Control: public, max-age=31536000` (files are immutable once uploaded)
- Return 404 if file doesn't exist

### 3. Extend the Message Model

The existing `POST /api/messages` endpoint already accepts `messageType` and `mediaFileId`. We just need to support a few new message types:

```
messageType values:
  "TEXT"       — Plain text (existing, default)
  "IMAGE"      — Message contains an uploaded image
  "GIF"        — Message contains an uploaded GIF
  "MIXED"      — Message contains text + one or more attachments
```

When `messageType` is `"IMAGE"` or `"GIF"`:
- `mediaFileId` should reference the ID returned from `POST /api/chat/upload`
- `content` can optionally contain a text caption

When returning messages via `GET /api/messages/channel/{channelId}`, include the file metadata inline:

```json
{
  "id": 501,
  "channelId": 1,
  "userId": 7,
  "username": "alex",
  "content": "Check this out!",
  "messageType": "IMAGE",
  "mediaFileId": 12345,
  "attachment": {
    "id": 12345,
    "url": "/api/chat/files/12345",
    "thumbnailUrl": "/api/chat/files/12345/thumb",
    "originalFilename": "screenshot.png",
    "mimeType": "image/png",
    "width": 1920,
    "height": 1080,
    "fileSize": 245760
  },
  "createdAt": "2026-04-03T12:00:00Z"
}
```

### 4. HSQLDB Schema Addition

Add a table (or extend an existing one) to store chat file metadata:

```sql
CREATE TABLE IF NOT EXISTS chat_files (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    original_filename VARCHAR(500) NOT NULL,
    stored_filename VARCHAR(500) NOT NULL,
    mime_type VARCHAR(100) NOT NULL,
    file_size BIGINT NOT NULL,
    width INT,
    height INT,
    thumbnail_filename VARCHAR(500),
    uploaded_by INT NOT NULL,
    channel_id INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (uploaded_by) REFERENCES players(id)
);
```

And add a column to the existing messages table if not already there:

```sql
ALTER TABLE messages ADD COLUMN IF NOT EXISTS media_file_id BIGINT;
ALTER TABLE messages ADD COLUMN IF NOT EXISTS message_type VARCHAR(20) DEFAULT 'TEXT';
```

## What We Implement on the Bridge Side

### 1. `lexicon-client.js` — New Methods

Add these methods to the existing `LexiconClient` class:

```javascript
/**
 * Upload a chat image/GIF to Lexicon.
 * @param {Buffer} fileBuffer - The raw file data
 * @param {string} filename - Original filename
 * @param {string} mimeType - MIME type (image/png, image/gif, etc.)
 * @param {number} userId - Lexicon user ID
 * @param {number} channelId - Channel where file is being shared
 * @returns {object} Upload response with id, url, thumbnailUrl, dimensions
 */
async uploadChatFile(fileBuffer, filename, mimeType, userId, channelId) {
  const FormData = require('form-data');
  const form = new FormData();
  form.append('file', fileBuffer, { filename, contentType: mimeType });
  form.append('userId', String(userId));
  form.append('channelId', String(channelId));

  const res = await fetch(`${this.baseUrl}/api/chat/upload`, {
    method: 'POST',
    body: form,
    headers: form.getHeaders(),
  });

  if (!res.ok) {
    const err = await res.text();
    throw new Error(`Chat file upload failed: ${res.status} - ${err}`);
  }
  return res.json();
}

/**
 * Get the full URL for a chat file.
 */
getChatFileUrl(fileId) {
  return `${this.baseUrl}/api/chat/files/${fileId}`;
}

getChatFileThumbnailUrl(fileId) {
  return `${this.baseUrl}/api/chat/files/${fileId}/thumb`;
}
```

**Dependency needed:** `npm install form-data` (for multipart uploads from Node.js)

## Frontend Changes (`chat.js`)

### 1. Message Content Renderer — `formatMessageContent()`

Add a new function that processes message text and converts:

- **URLs → clickable links** (auto-detect `http://`, `https://`, `www.`)
- **Image URLs → inline image previews** (`.png`, `.jpg`, `.gif`, `.webp`)
- **Markdown-style links → clickable links** (`[text](url)`)

```javascript
function formatMessageContent(text) {
  if (!text) return '';

  let html = escapeHtml(text);

  // Convert URLs to clickable links
  // Matches http://, https://, and www. URLs
  html = html.replace(
    /(?:https?:\/\/|www\.)[^\s<]+[^\s<.,;:!?"')\]]/gi,
    (url) => {
      const href = url.startsWith('www.') ? 'https://' + url : url;
      // Check if URL points to an image
      if (/\.(png|jpe?g|gif|webp)(\?[^\s]*)?$/i.test(url)) {
        return `<a href="${href}" target="_blank" rel="noopener noreferrer" class="chat-link">${url}</a>
                <div class="embed-image">
                  <img src="${href}" alt="Linked image" loading="lazy"
                       onclick="window.open('${href}','_blank')"
                       onerror="this.parentElement.style.display='none'">
                </div>`;
      }
      return `<a href="${href}" target="_blank" rel="noopener noreferrer" class="chat-link">${url}</a>`;
    }
  );

  return html;
}
```

### 2. Update `addChatMessage()` to Support Rich Content

Replace the current `escapeHtml(cleanText)` rendering with `formatMessageContent()`, and add support for image attachments:

```javascript
function addChatMessage(msg, isHistory) {
  // ... existing dedup/grouping logic ...

  const cleanText = stripHtml(msg.text || msg.content || '');
  const isImageMsg = msg.type === 'image' || msg.messageType === 'IMAGE' || msg.messageType === 'GIF';

  let contentHtml = '';

  // Text content (caption or full message)
  if (cleanText) {
    contentHtml += `<div class="message-text">${formatMessageContent(cleanText)}</div>`;
  }

  // Image attachment
  if (isImageMsg && (msg.fileUrl || msg.thumbnailUrl || msg.attachment)) {
    const att = msg.attachment || msg;
    const imgUrl = att.thumbnailUrl || att.fileUrl || att.url;
    const fullUrl = att.fileUrl || att.url || imgUrl;
    const w = att.width ? Math.min(att.width, 400) : 400;
    const h = att.height && att.width ? Math.round((w / att.width) * att.height) : 'auto';

    contentHtml += `
      <div class="message-attachment">
        <img src="${imgUrl}" alt="${escapeHtml(att.originalFilename || 'image')}"
             class="chat-image ${att.mimeType === 'image/gif' ? 'chat-gif' : ''}"
             style="max-width:${w}px; height:${h === 'auto' ? h : h + 'px'}"
             loading="lazy"
             onclick="window.open('${fullUrl}','_blank')">
        ${att.originalFilename ? `<div class="attachment-filename">${escapeHtml(att.originalFilename)}</div>` : ''}
      </div>
    `;
  }

  // ... render into DOM with contentHtml instead of just escapeHtml(cleanText) ...
}
```

### 5. Paste / Drag-and-Drop Support

Add clipboard paste support for images (users pressing Ctrl+V with an image in clipboard):

```javascript
messageInput.addEventListener('paste', async (e) => {
  const items = e.clipboardData?.items;
  if (!items) return;

  for (const item of items) {
    if (item.type.startsWith('image/')) {
      e.preventDefault();
      const file = item.getAsFile();
      // Trigger the same upload flow
      const dt = new DataTransfer();
      dt.items.add(file);
      chatFileUpload.files = dt.files;
      chatFileUpload.dispatchEvent(new Event('change'));
      return;
    }
  }
});
```
